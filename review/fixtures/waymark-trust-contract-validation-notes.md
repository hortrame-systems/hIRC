# WAYMARK trust-contract fixture validation notes

WAYMARK supplied four valid-control and seven adverse variants against frozen v1
request, Bayesian-reliance and cooperative-competition schemas.

Exact v1 run:

- all eleven serialized variants passed PowerShell `Test-Json` 7.0.0.0;
- explicit semantic checks accepted the four controls and rejected the seven
  adverse cases; and
- this confirms the v1 schema gap without claiming a deployed bypass.

Versioned v2 candidate schemas added explicit privacy admission, honest intent
confidence, current authority/participation/effect coherence, valid Beta
parameters, signed metric/model-fit references, anti-social-score governance,
safe action profiles, active-contest consent and activation-validation evidence,
protected qualities and task-scoped credit.

The same cases were adapted only for those new required fields. v2 `Test-Json`
and semantic checks accepted all four controls and rejected all seven adverse
variants. The result is synthetic contract evidence. Serialized flags/references
do not prove current permission, consent, signature, identity distinctness,
eligibility, construct validity or runtime enforcement; dispatch/activation and
actual statistical/privacy/security/usability testing remain required.

The first v2 result retained the fixture's v1 binding block and therefore did
not independently identify its executed v2 targets. It remains preserved at a
producing-agent-reported target grade. A single bounded trace-repair rerun is
recorded in `waymark-trust-contract-validation-v2.1.json`; it includes exact v2
paths/hashes, per-case adapted-input hashes, harness hash, PowerShell engine,
validator module and outcomes. `validate_waymark_contract_cases_v2.1.ps1` is the
